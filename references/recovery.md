# 故障恢复决策表

> **何时读本文件**：只在**观测到具体故障**时读。
> 不要为了「以防万一」提前读，也不要把所有故障用同一套办法处理——
> 不同原因的修复手段互不通用，重复同一套修复只会浪费时间。

---

## 一、先诊断，再修复

出现故障时，第一步永远是**确认观测到的现象属于哪一类**，再选择对应的下一步。
下表左列是**观测**，右列是**含义与下一步**。

---

## 二、CLI 相关

| 观测 | 含义与下一步 |
|------|------------|
| `python` 命令不存在 / `command not found` | 环境没有 Python 或不在 PATH。确认 Python 版本 ≥ 3.10；本项目已验证可用的是系统 Python，不是托管 Python。 |
| `ModuleNotFoundError: No module named 'pandas'` | 依赖未安装。见 `requirements.txt`。注意：**托管 Python 通常没有 pandas**，需用系统 Python。 |
| `ModuleNotFoundError: No module named 'openpyxl'` | 同上，安装 `openpyxl>=3.1`。 |
| `Invalid JSON params: ...` | 参数 JSON 非法。最常见原因是在单引号内给双引号加了反斜杠转义。改用管道方式或 `--params-file`。 |
| PowerShell `ParserError` | 两个路径参数都被引号包裹了（如 `"python.exe" "run.py"`）。改为先 `cd {CLI_DIR}` 再用相对路径。 |
| `can't open file 'run.py'` | 没先 `cd {CLI_DIR}`，或 `{CLI_DIR}` 定位错误。重新执行 `glob **/conspect_tools/run.py`。 |
| `status: error, message: content_file 不存在` | 传了 `content_file` 但文件未创建。先用写文件工具落盘，再调用。 |
| `不支持的文件格式「.xxx」` | 数据源格式不在支持范围。当前支持 `.xlsx` / `.xlsm` / `.csv`。 |
| `不支持旧版 Excel 格式 .xls` | openpyxl 无法读取 BIFF。请用 Excel/WPS 另存为 `.xlsx` 后重试。 |
| `FileNotFoundError`（数据源） | 文件路径不存在。注意 Git Bash 的 `/tmp/x` 与 Windows Python 的路径不互通，**统一用盘符路径**（如 `e:/data/x.xlsx`）。 |
| 命令无输出且未报错 | 参数被 `sys.stdin.read()` 吞掉或为空。检查是否忘了写 JSON，或管道两端不是同一条命令。 |
| 想改用 `python -c "..."` 绕过以上问题 | **不要**。这绕过了工具层的异常降级与路径校验，且在 Windows PowerShell 下引号嵌套必然失败。写 `.py` 脚本文件执行也可以，但那是最后手段。 |

## 三、数据源相关

| 观测 | 含义与下一步 |
|------|------------|
| `load` 返回空字典 `{}` | 没有文件被成功读取。逐个确认：路径是否存在 → 后缀是否受支持 → 文件是否为空。 |
| `BadZipFile: File is not a zip file` | 这是 v3.1 及以前的旧现象（把 CSV/JSON 当成 xlsx 解）。v3.2 已改为可读错误提示；若仍见到此类报错，说明用的是旧版本代码。 |
| 某列全是空值 | 检查表头行是否为合并单元格；CLI 的前 3 行样本可帮助判断。 |
| 数值列被识别为文本 | 检查是否存在货币符号、千分位或全角字符；清洗规则见 `agents/01-analyzer-agent.md` 第 2.2 节。 |
| 分析结果与预期不符 | 先看 `read_all` 的原始样本，再核对 `_cs-analysis.md` 的清洗记录。**不要**直接改数据文件。 |

## 四、审核与阻断

| 观测 | 含义与下一步 |
|------|------------|
| QA 报告给出 C/D 级 | 读 `_cs-qa-{phase}.md` 的「待修复问题清单」，逐条修复后重新提交审核。 |
| 同一阶段重试已达 2 次 | 状态置为 `FAILED`，输出失败报告并建议人工介入。**不要**继续第 3 次自动重试。 |
| 出现 `_cs-qa-blocked.md` | 触发 P0 阻断（如产物含 emoji、关键文件缺失）。按报告中的修复指引处理后重提。 |
| 前置产物缺失导致无法进入下一阶段 | 回到产出该产物的阶段补齐。禁止跳过前置产物直接推进。 |

---

## 五、环境与权限

| 观测 | 含义与下一步 |
|------|------------|
| `PermissionError`（写产物） | 目标路径被占用或只读。确认 `.agent/harness/` 可写，关闭占用该文件的程序。 |
| `PermissionError`（读审核上下文） | 传入的路径为空时旧版本会把目录当文件打开。v3.2 已修复（返回空字典）；若仍出现，检查是否用了旧版 `review_data_loader`。 |
| PDF / Word 产物缺失 | playwright / python-docx 未安装，属**可选依赖**，渲染已降级为 HTML/Markdown 字节。如需该产物请安装对应依赖；不需要则忽略。 |
| 需要联网加载 ECharts CDN | 离线环境请使用离线模式（内联 ECharts），避免 CDN 拉取失败导致图表空白。 |

---

## 六、通用纪律

1. **先确认观测，再动手**——不要用「重装依赖」去解决一个路径问题。
2. **同一调用失败后，不要原样重试**。要么改变输入，要么先解除阻塞原因。
3. **保留原始故障信息**（报错原文、发生的动作、参数），它是定位的唯一线索。
4. **不可逆动作前先确认**：覆盖已有产物、删除文件、推送仓库等，须先说明将要发生什么。
