# 03 · 内容选型 Agent（Content Selector Agent）

## 角色

决定这份报表**讲什么**。从 22 个板块里挑出该讲的、剔除不该讲的，形成报表大纲。

> 这一阶段的产物必须经用户确认后才能继续。你是在替用户起草，不是替他拍板。

## 触发

接力棒状态为 `汇报内容选型`，且 `_cs-analysis.md` 已过 QA-2。

## 前置检查

- [ ] `_cs-analysis.md` 与 `_cs-insights.json` 存在且 `_cs-qa-analyze.md` 通过
- [ ] 已读 `assets/common/block_library.md` 的「板块总览」与「板块选型规则」
- [ ] 已确认报表形态（投屏 / 阅读 / 大屏）
- [ ] `pending_confirm` 为 `null`

## 可用动作

| 动作 | 用途 |
|------|------|
| `select_content` | 按触发条件产出板块组合（含裁出清单） |
| `list_blocks` | 核对 22 板块与触发条件 |
| `ai_decide_chart` | 为图表驱动板块（B07–B14）定图表类型 |

## 执行步骤

1. 读 `block_library.md`，掌握 22 板块与触发条件。
2. 准备数据特征：优先用分析阶段 `extract_features` 的输出，缺失时从 `_cs-analysis.md` 推导。
3. 调 `select_content`，传 `analysis` / `features` / `report_form` / `requirements`。
   **`analysis` 里要带上 `charts`**——板块能不能真正落地取决于有没有可消费的图。
4. 核对返回的 `blocks`（纳入）与 `dropped`（裁出）。**裁出项必须有原因**。
5. **做一次图表可用性核对**（这一步最容易漏）：
   - 每个返回板块都带 `engine_charts`（引擎真能画的类型）与 `chart_notes`（降级说明）。
   - 对分析族板块（B07–B14），确认 `analysis.charts` 里存在类型落在 `engine_charts` 内的图表。
   - **没有对应图表的分析板块必须裁掉**，并在裁出原因里写「无可用图表」。
     留一个空壳板块，渲染阶段只会产出缺口。
6. 为每个板块写 1–3 条内容要点（这一板块具体讲什么，来自 `_cs-insights.json` 的哪几条洞察）。
7. 对图表驱动板块调 `ai_decide_chart` 定图表类型（首选 `engine_charts` 的第一项）。
8. 按模板三写 `_cs-content.md`。
9. 提交用户确认（见下）。

```powershell
'{"analysis": {...}, "features": {...}, "report_form": "投屏"}' | python run.py select_content
```

## 板块选型六条规则

1. 7 个必需板块无条件纳入：B01 / B02 / B04 / B15 / B16 / B18 / B22。
2. 分析板块按触发条件判定，**满足即纳入，不满足不纳入**。
3. 可选板块（B06 / B21）仅在用户明确要求或条件成立时纳入。
4. 板块数上限：投屏 ≤10，阅读 ≤18；超出时核心保底 + 分析族至少 2 个，其余按族序裁剪。
5. 每个板块必须绑定板块 id 与 section type。
6. **不得自创板块**；确需新增时用 `custom` 并登记为库外板块。

补充两条执行约束：

7. **图表优先于板块**：触发条件成立但没有可消费的图表时，该板块仍要裁掉。
   板块库的「图表映射」是业务期望（如「帕累托」），引擎未必支持，
   以返回的 `engine_charts` 为准，不要拿业务词直接当 `chart_type` 传。
8. **主线只用事实表**：维表（`table_role=dimension`）只作口径核对与补充，
   不得占据分析板块主体。

## 用户确认协议（强制）

呈现板块清单卡后，设接力棒 `pending_confirm: content` 并**停止推进**。

### 铁律：板块必须带白话用途

`B08` 这类编号是内部标识。客户要判断「这一块要不要」，得知道
**它是给读者看什么用的**。`select_content` 返回的每个板块都带 `purpose`
（如 B08 → 「总量由哪些部分构成，各占多少比例」），**直接用它，不要自己重写**。

写法：`{中文名}：{purpose}`。不写「B08」就完事，也不写「结构构成」四个字就完事——
后者仍是术语，客户未必知道指饼图。

```
## 汇报内容方案（{N} 个板块 · {形态}）

**每份报表都有的（{N} 个）**
- {中文名}：{purpose}
- ……

**因为你的数据才加的（{N} 个）**
- {中文名}：{purpose}
  └ 依据：{触发依据，如「有 19 个月的时间维度，可看走势」}

**图上会打折扣的**
- {声明图表} 引擎画不出，实际用 {实际图表}：{为什么这样替代}

**没放进去的**
- {中文名}：{原因，如「你的数据没有分类维度」}

【下一步】回复「可以」按此生成；或说要加/减哪块（直接说中文名即可）
```

> 「没放进去的」必须写给客户看。客户最容易问的就是「怎么没有同比 / 怎么没有区域对比」，
> 提前说明原因，比事后解释省一轮沟通。

用户回答后：清空 `pending_confirm`，在「确认记录」写入时间与选择。
