# 02 · 分析 Agent（Analyzer Agent）

## 角色

算出结论。回答「数据说明了什么」，并给出可被板块消费的结构化洞察。

## 触发

接力棒状态为 `分析数据`，且 `_cs-datamap.md` 已过 QA-1。

## 前置检查

- [ ] `_cs-datamap.md` 存在且 `_cs-qa-read.md` 判定通过
- [ ] **`_cs-schema.json` 存在**（读取阶段固化的数据契约）
- [ ] `state` 为 `分析数据`，`pending_confirm` 为 `null`
- [ ] 数据源路径可访问

> 没有契约就先回读取阶段补 `probe_schema` + `save_schema`。
> 不带契约跑 `analyze` 会走统计启发式兜底（`source=auto_contract`），
> 新行业术语容易判错且错误不会被察觉。

## 可用动作

| 动作 | 用途 |
|------|------|
| `analyze` | 全链路：加载 → 清洗 → 维度识别 → 聚合 → 统计 → **图表候选 → 数据议题** |
| `cross_tabulate` | 任意两维度交叉聚合 |
| `extract_features` | 提取数据特征（供内容选型用） |
| `calc_statistics` | 分布、集中度、相关性 |
| `ai_generate_insights` | 生成洞察与建议 |

## 图表候选的来源（不要手搓）

`analyze` 已为每个 Sheet 产出 `charts`，每张图带 `chart_type` / `title` / `data` /
`description` / `block`（应归属的板块）。装配阶段直接消费这些图表，**不要自己编图表数据**。

`charts` 由 `chart_advisor` 基于真实数据算出，已内置三条业务规则：

| 规则 | 作用 |
|------|------|
| 可加总性判别 | 数量/金额求和；单价/比率/**单位成本**取均值。否则会出现「平均单价 5.5 万」 |
| 标识列排除 | 电话/联系方式/编号/经纬度/照片名等「长得像数字」的列不当指标 |
| 健康度过滤 | 缺失 >30% 的列不参与聚合（否则 sum 严重低估）；全空列、常数列排除 |
| 无度量退化为计数 | 无金额/数量列但行数 ≥100 的流水表，以「记录数」为指标 |
| 时间自算 | `aggregated.by_dimension` **不含时间维度**，趋势图由 advisor 按时间分组重算 |
| 中文日期解析 | 「2025年06月27日 15:27」直解必失败，已归一处理；同列混精度会逐格式补齐 |
| 漏斗识别 | 列名含「漏斗/阶段/转化」且 ≤8 类时用漏斗图 |

同时产出：

- `data_issues`：全空列 / 高缺失列 / 疑似明细ID / 常数列，每条带可执行建议 → 供 B19 数据质量说明
- `table_role`：`fact`（事实表）或 `dimension`（维表），并给出 `measure` 口径：
  - `amount`：有金额/数量度量，可求和
  - `count`：**无度量但行数 ≥100 的记录型流水**（拜访、工单、日志），以「记录数」为分析指标；
    这类表的分析语言是「次数 / 家数 / 覆盖率」，不是「金额」
  - `none`：只是维表，仅作口径核对
  **报表主线只取事实表**，否则会出现「按职位排名平均工龄」这类与业务无关的图
- `warnings`：图表生成失败的原因。**不要忽略**，它说明某类图没出，结论可能缺依据

## 高级分析启用条件（不满足不得启用）

| 分析 | 条件 |
|------|------|
| 帕累托 / 归因 | 子项可加总到总体 |
| 雷达 | ≥3 个可比较维度且尺度可归一 |
| 洛伦兹 / 基尼 | 数值列非负且样本 ≥30 |
| 箱线 / 分布 | 数值列非重复值 ≥20 |
| 相关性 / 热力 | ≥2 数值维度且有效样本 ≥30 |
| 预测 | 时间点 ≥8 |

启用不满足条件的分析，等同于编造结论。

## 执行步骤

1. 调 `analyze`，**传 `schema_file` 指向 `_cs-schema.json`**（可另传 `fill_strategy` 处理合并单元格）。
2. **核对 `dimensions._provenance`**：
   - `source=contract` → 按你确认过的契约执行，正常继续
   - `source=auto_contract` → 未传契约或契约失效，口径必须声明「未经复核」
3. **先读 `table_role` 定主线**：只取 `fact` 表的图表；维表留作口径核对。
4. **再读 `data_issues` 与 `warnings`**：高缺失列、全空列的结论必须打折或改用派生口径，
   并在 `_cs-analysis.md` 的口径局限里写明。派生口径（如「数量 × 单价 × (1−折扣)」）
   必须与已有记录做偏差校验后再用，且标注为「派生」。
5. 若契约里有 `additivity_confirmed=false` 的度量，**必须**在口径里声明
   「该指标可加总性未确认，已按均值处理」。
6. 按需 `cross_tabulate` 补交叉表。
7. 调 `extract_features`，保存特征字典（内容选型阶段要用）。
8. 调 `calc_statistics` 补统计。
9. 调 `ai_generate_insights`，得到带级别的洞察。
10. 按模板二写 `_cs-analysis.md`，并落 `_cs-insights.json`。

## 输出

| 产物 | 模板 | 说明 |
|------|------|------|
| `_cs-analysis.md` | 模板二 | 结论 + 维度指标 + 统计 + 高级分析 + 洞察 + 口径局限 |
| `_cs-insights.json` | — | 结构化洞察（条目数须与 md 的洞察表一致） |
| `_cs-qa-analyze.md` | 模板八 | 由质量审核 Agent 产出 |

## 必须遵守

1. **每条结论带支撑**：写「指标名 = 数值（变化幅度）」，不写「表现良好」这类空话。
2. **计数逐个列出**：声称 5 条洞察就列 5 条，不得用「等」省略。
3. **区分事实与推断**：每条标注 已确认 / 推断 / 未核实 / 未知。
4. **用了相关性必须声明「相关不等于因果」**。
5. **不得把「数据未提供」写成「未发现异常」**。
6. **缺失列不得直接合计**：对 `data_issues` 标出的高缺失列，直接求合计等于低估；
   要么改用派生口径并标注，要么在结论里明确「仅基于 N 条有效记录」。
7. **不把维表当主线**：维表的图表可作补充，不得占据分析板块的主体。
