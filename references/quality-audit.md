# 质量审核机制

> 本文档定义 conspect Skill 的质量审核机制，包括审核执行者、审核时机、审核检查清单和审核不通过处理。

---

## 一、审核执行者：AI 审核 Agent（子 Agent）

**为什么使用子 Agent 进行审核？**

1. **避免上下文污染**：
   - 审核过程需要读取大量文件（分析结果、设计文档、实现文档、原始数据）
   - 如果在主对话中执行，会占用大量上下文窗口
   - 使用子 Agent，审核在独立上下文中进行，不污染主对话

2. **并行执行**：
   - 多个审核任务可以并行执行
   - 提高审核效率

3. **专注审核**：
   - 子 Agent 只负责审核，不受其他任务干扰
   - 审核更深入、更全面

---

## 二、审核时机

| 门 | 位置 | 审核内容 | 输出文件 |
|----|------|---------|---------|
| QA-1 | 读取数据后 | 数据源是否全枚举、质量分是否已算 | `_cs-qa-read.md` |
| QA-2 | 分析数据后 | 结论是否有数据支撑 | `_cs-qa-analyze.md` |
| QA-3 | 汇报内容选型后 | 板块组合是否覆盖结论 | `_cs-qa-content.md` |
| QA-4 | 报表选型后 | 资产引用是否有效、有无禁忌违反 | `_cs-qa-style.md` |
| QA-5 | 生成报表后 | 板块是否逐个落地、合规是否达标 | `_cs-qa-render.md` |

## 三、审核检查清单

### 数据一致性审核
- [ ] 图表数据是否与分析结果一致？
- [ ] 分析结果是否与原始数据一致？
- [ ] 实现数据是否与设计数据一致？
- [ ] 数据链路是否完整（原始数据 → 分析 → 设计 → 实现）？

### 设计合理性审核
- [ ] 图表类型是否适合数据特征？
- [ ] 配色方案是否符合业务场景？
- [ ] 布局是否合理？
- [ ] 信息层级是否清晰？

### 实现正确性审核
- [ ] 图表是否正确渲染？
- [ ] 交互功能是否完整？
- [ ] 文件是否正确生成？

### 业务逻辑审核
- [ ] 数据表达是否符合业务逻辑？
- [ ] 洞察是否有业务价值？
- [ ] 建议是否可执行？

---

## 四、审核不通过处理

- 审核不通过 → 阻断流程 → 输出审核报告 → 必须修复
- 修复后重新审核 → 直到通过
- 重试超过 2 次 → FAILED → 需人工介入
