# conspect 接力棒协议（v4.0）

> 接力棒是跨 Session 的唯一现场。它记录「走到哪、下一步做什么、在等谁」。
> 文件路径固定：`{项目路径}/.agent/harness/_cs-baton.md`

## 一、状态枚举（5 阶段 + 2 终止态）

```
读取数据 / 分析数据 / 汇报内容选型 / 报表选型 / 生成报表 / 完成 / FAILED
```

**没有 `待确认` 状态**——确认点是阶段内的检查点，用 `pending_confirm` 字段表达，
这样状态列表保持 5 个，一眼看得清。

## 三、字段纪律

| 字段 | 规则 |
|------|------|
| `当前状态` | 只能取 7 个枚举值之一，不得自造 |
| `pending_confirm` | `null` / `content` / `style`；非 null 时禁止推进 |
| `重试计数` | 任一质量门打回即 +1；进入下一阶段时归零 |
| `风格族` | 六族 id 之一（biz/screen/glass/editorial/organic/bold） |
| `选择记录` | 报表选型必须写入完整的 `[资产引用]` 行 |

## 四、生命周期

| 时机 | 操作 |
|------|------|
| 首次启动 | 创建目录与接力棒，状态置 `读取数据`，预填产物清单为「未开始」 |
| 每阶段结束 | 更新状态、产物状态、质量门结果、最后更新时间 |
| 确认点触发 | 写 `pending_confirm`，同时在「确认记录」标记「待确认」 |
| 用户确认 | 清 `pending_confirm`，记录选择与时间 |
| 用户中断 | 按用户选择：重置状态 / 记入待办 / 仅讨论，并记录中断原因 |
| 到达完成 | 状态置 `完成`，写最终汇总报告路径 |
| 新任务 | 状态重置为 `读取数据`，**清空选择记录与确认记录**，保留历史产物 |

## 五、跨 Session 续跑

新会话读到接力棒时：

1. 若 `pending_confirm` 非空 → **先向用户复述待确认内容与选项**，不推进。
2. 若 `当前状态` 为 `完成` 或 `FAILED` → 提示用户这是上一个任务的收尾，询问是否开新任务。
3. 其余情况 → 回复「当前状态：[状态]，下一步：[操作]」，从未完成的阶段继续。

**续跑不重做已完成阶段**：已有产物且质量门通过的不再重跑，除非用户要求。
