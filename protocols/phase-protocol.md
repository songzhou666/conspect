# conspect 阶段流转协议（v4.0）

> 定义 5 阶段的检查点、质量门、确认点与回退边。
> **状态机图与阶段定义表以 [SKILL.md 第三节](../SKILL.md) 为准，本文件只定义流转规则。**

## 一、流转示意

```
读取数据 ─QA1→ 分析数据 ─QA2→ 汇报内容选型 ⟪确认⟫ ─QA3→ 报表选型 ⟪确认⟫ ─QA4→ 生成报表 ─(内核验)→ QA5→ 完成
   ↑              ↑                    ↑              ↑                │
   └─ 数据不可读 ──┴─ 结论无支撑 ────────┴─ 风格不匹配 ──┴─ 数据不一致 ──┘
```

- **质量门不是状态**：5 个阶段配 5 道门，门是阶段之间的检查。
- **验证不是状态**：验证降为「生成报表」阶段的内核验回路。
- 同一道门打回上限 2 次；超限状态置 `FAILED`。

## 二、五道质量门

| 门 | 位置 | 核心判定 |
|----|------|---------|
| QA-1 | 读取数据 → 分析数据 | 数据源全枚举、列与类型齐全、质量分已算 |
| QA-2 | 分析数据 → 汇报内容选型 | 结论有数据支撑、高级分析满足启用条件 |
| QA-3 | 汇报内容选型 → 报表选型 | 7 必需板块齐备、每板块有触发依据、分析族 ≥2 |
| QA-4 | 报表选型 → 生成报表 | `[资产引用]` 声明有效、无 taboo 违反、载体不冲突 |
| QA-5 | 生成报表 → 完成 | 板块逐个落地、无 emoji、语义不只靠颜色、无明细泄露 |

各门的具体检查项见 [SKILL-execution.md](../SKILL-execution.md) 对应章节的「检查点」。

## 三、两个强制确认点

| 确认点 | 触发时机 | 接力棒字段 | 未确认的后果 |
|--------|---------|-----------|-------------|
| 内容确认 | `_cs-content.md` 过 QA-3 后 | `pending_confirm: content` | 禁止进入报表选型 |
| 风格确认 | `_cs-style.md` 过 QA-4 后 | `pending_confirm: style` | 禁止进入生成报表 |

**规则**：

1. `pending_confirm` 非 `null` 时，接力棒的 `state` 停在当前阶段，不得推进。
2. 用户确认后必须清空该字段，并记录确认时间与用户选择。
3. 用户要求调整时，回到本阶段第 2 步重做，重新过门，再确认一次。
4. 确认点**不可用「默认继续」代替**——沉默不等于同意。

## 四、回退边（全 8 条）

| 触发 | 回退到 | 计入重试 |
|------|--------|---------|
| 数据不可读 / 列含义不明 / 口径缺失 | 读取数据 | 否 |
| 分析结论与数据矛盾（DATA_MISMATCH） | 分析数据 | 是（retry ≤2） |
| 必需板块覆盖不到已确认的结论 | 汇报内容选型 | 否 |
| 风格与报表类型或载体冲突 | 报表选型 | 否 |
| 用户要求换板块 | 汇报内容选型 | 否 |
| 用户要求换风格 | 报表选型 | 否 |
| 渲染失败（模板/样式/装配） | 生成报表（本阶段修复） | 是（retry ≤2） |
| 依赖缺失（ENVIRONMENT） | 不自动回退，报告用户 | 否 |

## 五、阻断规则

触发任一条件即阻断流转，须先修复：

1. **前置产物不存在** → 阻断进入下一阶段
2. **质量门未通过** → 阻断进入下一阶段
3. **确认点未确认** → 阻断进入下一阶段
4. **`[资产引用]` 缺失或编号无效** → 阻断生成
5. **同一门重试超过 2 次** → 状态置 `FAILED`，需人工介入
6. **产物路径不一致** → 阻断交付（必须写入 `{项目路径}/.agent/harness/`）

## 六、验证链规则

- **计数验证**：声称「N 个」必须逐个列出 N 个
- **列表验证**：涉及文件必须列出具体路径，不得用「等」省略
- **文件验证**：产物写入后必须 `read` 确认
- **流程图验证**：必须使用标准 Mermaid 语法
- **证据分级**：每条结论标注 已确认 / 推断 / 未核实 / 未知

任一未通过 → 视为阶段未完成。
